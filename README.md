# Queue Bot (Go)

Telegram-бот для управления очередями студентов на сдачу лабораторных работ.

Бот автоматически открывает очередь по расписанию (с учётом чётности недели), рассылает уведомления за 5 минут и за 1 минуту до начала, после закрытия - сбрасывает всё для следующего раза. Очередь можно открыть и вне расписания одноразовой командой.

## Стек

| Компонент | Технология |
|-----------|-----------|
| Язык | Go 1.25 (Docker и CI) |
| Telegram API | [go-telegram/bot](https://github.com/go-telegram/bot) v1.19 |
| База данных | PostgreSQL 16 |
| Драйвер БД | pgx/v5 |
| Миграции | golang-migrate/migrate v4 |
| Конфигурация | `.env` для доступа, `config.yaml` для начальных настроек, PostgreSQL для изменений из бота |
| Деплой | Docker Compose + GitHub Actions |

## Возможности

- Расписание с чётными / нечётными неделями, которые начинаются в понедельник по московскому времени
- Мгновенная смена текущей чётности в `/edit_schedule`; уже открытые очереди продолжают работать
- Уведомления за 5 мин и за 1 мин до открытия очереди
- Повтор операций планировщика после временных ошибок с увеличением интервала между попытками
- Запись в очередь, выход, занятие первого свободного слота
- Независимые очереди в разных группах и темах; одна действующая очередь на тему
- Отметка сдачи после имени: участник отмечает себя, администратор — любое занятое место
- Необязательный заголовок очереди, отдельный от описания расписания
- Одноразовая очередь `/one_shot_queue [заголовок]` — по умолчанию открывается через 6 минут на 90 минут
- Редактирование расписания прямо из Telegram (inline-меню)
- Проверка прав администраторов, сессий редактирования и актуального сообщения очереди
- Последовательная обработка действий одного пользователя / темы и параллельная работа разных тем

## Быстрый старт (локально)

### 1. Клонировать репозиторий

```bash
git clone https://github.com/<your-user>/queue-bot-go.git
cd queue-bot-go
```

### 2. Создать `.env`

Скопируй `.env.example` в `.env` и заполни инфраструктурные параметры. Начальные несекретные настройки очередей находятся в `config.yaml`; изменения через `/edit_config` применяются сразу и сохраняются между перезапусками. Размер и сетка применяются к новым очередям, уже открытые сохраняют свои настройки. Прежние переменные окружения для очереди поддерживаются при первоначальном заполнении настроек.

`DEVELOPER_USER_ID` задаётся только через окружение; по умолчанию это `789915524`. Только этот пользователь может открыть `/edit_config`.

Создание `.env`:

```bash
cp .env.example .env
```

| Переменная | Описание |
|------------|----------|
| `BOT_TOKEN` | Токен бота от @BotFather |
| `BOT_CHAT_ID` | Основная группа для старого расписания и команд из личного чата; команды в группах используют текущую группу |
| `AUTHORIZED_USER_ID` | ID администраторов через запятую, напр. `123456,789012` |
| `DEVELOPER_USER_ID` | ID разработчика с доступом к `/edit_config`, по умолчанию `789915524` |
| `QUEUEBOT_PORT` | Порт контейнера бота (напр. `5001`) |
| `DB_USER` | Имя пользователя PostgreSQL |
| `DB_PASSWORD` | Пароль PostgreSQL |
| `DB_NAME` | Имя базы данных |
| `DB_PORT` | Порт PostgreSQL (напр. `5432`) |
| `DB_HOST` | Хост БД; для Docker Compose - `postgres` |
| `PGADMIN_PORT` | Порт pgAdmin (напр. `5050`) |
| `PGADMIN_EMAIL` | Email для входа в pgAdmin |
| `PGADMIN_PASS` | Пароль для входа в pgAdmin |
| `PGADMIN_REQUIRE_LOGIN` | `True` в проде, `False` локально |
| `PGADMIN_REQUIRE_PASS` | `True` в проде, `False` локально |

> **`DB_HOST`**: при запуске через Docker Compose должен быть `postgres` (имя сервиса).  
> Локально без Docker - `localhost`.

В `config.yaml` задаются начальные настройки:

| Параметр | Описание |
|----------|----------|
| `total_slots_in_queue` | Количество мест в новых очередях |
| `amount_of_buttons_in_row` | Число кнопок мест в одной строке |
| `week1_date`, `week1_type` | Опорная дата и тип её недели (`odd` / `even`); отсчёт идёт от понедельника |
| `one_shot_delay`, `one_shot_duration` | Задержка открытия и длительность разовой очереди, например `6m` и `90m` |
| `delay_update_queue` | Интервал объединения обновлений сообщения, например `400ms` |
| `edit_session_timeout` | Таймаут сессии редактирования, например `4m` |
| `scheduler_tick_interval` | Интервал проверки событий планировщика, например `1s` |
| `update_workers` | Количество исполнителей обновления сообщений; задаётся при запуске и не редактируется из бота |

Токен, параметры подключения к БД и ID доступа задаются только через окружение. В меню `/edit_config` их нет.

### 3. Запустить через Docker Compose

```bash
docker compose up -d --build
```

Контейнеры:

| Контейнер | Назначение |
|-----------|-----------|
| `queuebot` | Сам бот |
| `queuebot_db` | PostgreSQL |
| `queuebot_pgadmin` | pgAdmin 4 (веб-интерфейс БД) |

Миграции применяются автоматически при старте бота. Текущие запуски сохраняют даты, участников и отметки между перезапусками. Для очередей старой версии дата восстанавливается из исходной даты сообщения Telegram, без привязки к сегодняшнему дню. Если исходное сообщение недоступно, участники сохраняются, но автоматически восстановить дату такой очереди нельзя.

## Команды бота

### Пользователи

| Команда | Описание |
|---------|----------|
| `/start` | Показать приветствие |
| `/swap <место>` | Запросить обмен местами в текущей теме очереди |

### Администраторы

| Команда | Описание |
|---------|----------|
| `/edit_schedule` | Редактировать расписание и сразу сменить чётность текущей недели |
| `/edit_config` | Изменить настройки бота; только для `DEVELOPER_USER_ID` |
| `/queue` | Восстановить удалённое сообщение текущей очереди без потери участников |
| `/one_shot_queue [заголовок]` | Создать одноразовую очередь; задержка и длительность задаются в конфиге |

Заголовок можно оставить пустым или передать после команды:

```text
/one_shot_queue БГГ323 — Высоконагруженные приложения
```

Он отображается первым абзацем над текстом очереди. В `/edit_schedule` заголовок редактируется отдельно от описания; при добавлении записи это последнее необязательное поле после описания.

Кнопка «✅ Сдал / отменить» переключает отметку самого участника. Администратор может нажать на занятое место другого участника. Галочка появляется после имени, не освобождает место и остаётся у человека при обмене.

## Деплой на сервер (GitHub Actions)

Пуш в ветку `main` запускает unit/race-проверки, интеграционные тесты с PostgreSQL и сборку контейнера. Деплой через SSH выполняется после успешного завершения всех проверок для того же коммита. Готовность контейнера подтверждается после подключения к БД, применения миграций, проверки Telegram и загрузки расписания.

### Необходимые секреты в GitHub репозитории

| Секрет | Значение |
|--------|----------|
| `GO_BOT_SERVER_HOST` | IP или домен сервера |
| `GO_BOT_SERVER_USER` | SSH-пользователь |
| `GO_BOT_SSH_PRIVATE_KEY` | Приватный SSH-ключ |

### Настройка сервера (один раз)

1. **Сгенерировать SSH-ключ** (если нет):
   ```bash
   ssh-keygen -t ed25519 -C "github-actions"
   ```

2. **Добавить публичный ключ в `authorized_keys`**:
   ```bash
   cat ~/.ssh/id_ed25519.pub >> ~/.ssh/authorized_keys
   ```

3. **Добавить приватный ключ в GitHub Secrets** (`GO_BOT_SSH_PRIVATE_KEY`):
   ```bash
   cat ~/.ssh/id_ed25519
   ```

4. **Клонировать репозиторий на сервере**:
   ```bash
   git clone https://github.com/<your-user>/queue-bot-go.git ~/queue-bot-go
   ```

5. **Создать `.env` на сервере**:
   ```bash
   cp ~/queue-bot-go/.env.example ~/queue-bot-go/.env
   # Заполнить .env
   ```

После этого любой пуш в `main` автоматически пересоберёт и перезапустит контейнер бота. Перед первым обновлением с изменением схемы нужно самостоятельно сохранить резервную копию БД.

Для отката на версию до миграции №8 недостаточно переключить ветку: старый образ не знает эту версию схемы. Нужно остановить бота, восстановить выбранную резервную копию БД и запустить соответствующий ей старый код. Восстановление возвращает данные к моменту копии; последующие изменения в неё не входят. Автоматический downgrade с удалением настроек и отметок не выполняется.

## Структура проекта

```
queue-bot-go/
├── cmd/server/main.go              # Инициализация и запуск бота
├── config/config.go                # Загрузка окружения и начальных настроек
├── config.yaml                     # Несекретные начальные настройки
├── settings/                       # Валидация и сохранение изменений настроек
├── dispatch/                       # Упорядоченная обработка событий Telegram
├── queue/                          # Действия с очередью и обновление сообщения
├── db/
│   ├── db.go                       # Подключение к БД, запуск миграций
│   ├── models.go                   # Модели данных
│   ├── queue_repo.go               # CRUD для очереди
│   └── schedule_repo.go            # CRUD для расписания
├── handlers/                       # Команды, callback-и и представление сообщений
├── middleware/
│   ├── admin.go                    # AdminOnly
│   ├── chain.go                    # Цепочка middleware
│   ├── edit_session.go             # EditSession
│   └── queue_open.go               # QueueOpen
├── scheduler/scheduler.go          # Планировщик с retry-логикой
├── migrations/                     # SQL миграции (golang-migrate)
├── Dockerfile
├── docker-compose.yml
├── .env.example
└── .github/workflows/deploy.yml    # CI/CD
```
