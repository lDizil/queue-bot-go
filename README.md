# Queue Bot (Go)

Telegram-бот для управления очередями студентов на сдачу лабораторных работ.

Бот автоматически открывает очередь по расписанию (с учётом чётности недели), рассылает уведомления за 5 минут и за 1 минуту до начала, после закрытия - сбрасывает всё для следующего раза. Очередь можно открыть и вне расписания одноразовой командой.

## Стек

| Компонент | Технология |
|-----------|-----------|
| Язык | Go 1.25 (Docker и CI) |
| Telegram API | [go-telegram/bot](https://github.com/go-telegram/bot) v1.27 |
| База данных | PostgreSQL 16 |
| Драйвер БД | pgx/v5 |
| Миграции | golang-migrate/migrate v4 |
| Конфигурация | `.env` для доступа, `config.yaml` для начальных настроек, PostgreSQL для изменений из бота |
| Деплой | Docker Compose + GitHub Actions |

## Возможности

- Расписание с чётными / нечётными неделями, которые начинаются в понедельник по московскому времени
- Мгновенная смена текущей чётности в `/edit_schedule`; уже открытые очереди продолжают работать
- Уведомления за 5 мин и за 1 мин до открытия очереди
- Повтор операций планировщика после временных ошибок с увеличением интервала между попытками
- Запись в очередь, выход, занятие первого свободного слота и обмен местами с подтверждением
- Независимые очереди в разных группах и темах; одна действующая очередь на тему
- Отметка сдачи после имени: участник отмечает себя, администратор с разрешением — другого участника
- Необязательный заголовок очереди, отдельный от описания расписания
- Одноразовая очередь `/one_shot_queue [заголовок]` — по умолчанию открывается через 6 минут на 90 минут
- Редактирование расписания прямо из Telegram (inline-меню): выбор чата, затем его записей
- Список чатов с названиями и основным чатом для команд из лички
- Отдельные разрешения для каждого администратора; новые администраторы получают доступы только после включения разработчиком
- Управление участниками открытых очередей: живой список, удаление с временной блокировкой или без неё, ручная разблокировка
- Личные меню конфига и управления участниками внутри группы
- Удаление служебных меню по завершении сессии с повтором очистки после перезапуска
- Проверка разрешений, сессий редактирования и актуального сообщения очереди
- Последовательная обработка действий одного пользователя / темы и параллельная работа разных тем

## Быстрый старт (локально)

### 1. Клонировать репозиторий

```bash
git clone https://github.com/lDizil/queue-bot-go.git
cd queue-bot-go
```

### 2. Создать `.env`

Скопируй `.env.example` в `.env` и заполни инфраструктурные параметры. Если прежних администраторов нет, оставь `AUTHORIZED_USER_ID=` пустым, убрав шаблонное значение. Начальные несекретные настройки очередей находятся в `config.yaml`; после первого заполнения сохранённые в БД настройки имеют приоритет над файлом и прежними переменными окружения. Исключение — `update_workers`: он читается при каждом запуске.

Изменения через `/edit_config` сохраняются между перезапусками. Размер и сетка применяются к новым очередям, срок блокировки — к новым сессиям управления участниками; остальные настройки применяются после сохранения.

`DEVELOPER_USER_ID` обязателен: укажи положительный Telegram ID разработчика в окружении. Только этот пользователь может открыть `/edit_config`.

Создание `.env`:

```bash
cp .env.example .env
```

| Переменная | Описание |
|------------|----------|
| `BOT_TOKEN` | Токен бота от @BotFather |
| `BOT_CHAT_ID` | Необязательный ID для первоначального переноса старого расписания и выбора основного чата; по умолчанию `0`. Сохранённый в боте основной чат имеет приоритет |
| `AUTHORIZED_USER_ID` | ID прежних администраторов через запятую; импортируются один раз с полными разрешениями. Дальше доступами управляет разработчик через бота |
| `DEVELOPER_USER_ID` | Обязательный положительный Telegram ID разработчика с доступом к `/edit_config` |
| `QUEUEBOT_PORT` | Порт хоста в пробросе Docker Compose (напр. `5001`); бот получает события через long polling, HTTP API не поднимает |
| `DB_USER` | Имя пользователя PostgreSQL |
| `DB_PASSWORD` | Пароль PostgreSQL |
| `DB_NAME` | Имя базы данных |
| `DB_PORT` | Порт PostgreSQL; для текущего Docker Compose укажи `5432` — это же значение бот использует внутри сети контейнеров |
| `DB_HOST` | Хост БД; для Docker Compose - `postgres` |
| `PGADMIN_PORT` | Порт pgAdmin (напр. `5050`) |
| `PGADMIN_EMAIL` | Email для входа в pgAdmin |
| `PGADMIN_PASS` | Пароль для входа в pgAdmin |
| `PGADMIN_REQUIRE_LOGIN` | `True` в проде, `False` локально |
| `PGADMIN_REQUIRE_PASS` | `True` в проде, `False` локально |

> **`DB_HOST`**: при запуске через Docker Compose должен быть `postgres` (имя сервиса).  
> Локально без Docker - `localhost`.

В `config.yaml` задаются начальные настройки:

| Параметр | Описание |
|----------|----------|
| `total_slots_in_queue` | От 1 до 90 мест в новых очередях, по умолчанию `30` |
| `amount_of_buttons_in_row` | От 1 до 8 кнопок мест в строке, по умолчанию `5` |
| `week1_date`, `week1_type` | Опорная дата и тип её недели (`odd` / `even`); отсчёт идёт от понедельника |
| `one_shot_delay`, `one_shot_duration` | Задержка открытия и длительность разовой очереди: от `1m` до `168h`, по умолчанию `6m` и `90m` |
| `moderation_block_duration` | Срок запрета повторной записи: от `1s` до `24h`, по умолчанию `3m`; применяется к новым сессиям управления |
| `delay_update_queue` | Интервал объединения обновлений сообщения: от `50ms` до `30s`, по умолчанию `400ms` |
| `edit_session_timeout` | Таймаут сессии редактирования: от `30s` до `24h`, по умолчанию `4m` |
| `scheduler_tick_interval` | Интервал проверки событий планировщика: от `100ms` до `1m`, по умолчанию `1s` |
| `update_workers` | От 1 до 32 исполнителей обновления сообщений, по умолчанию `4`; задаётся при запуске и не редактируется из бота |

Токен, параметры подключения к БД и ID разработчика задаются через окружение. Токена и параметров БД в `/edit_config` нет; администраторами и их разрешениями управляем через вкладку «Администраторы».

### 3. Запустить через Docker Compose

```bash
docker compose up -d --build
```

Контейнеры:

| Контейнер | Назначение |
|-----------|-----------|
| `queuebot` | Сам бот |
| `queuebot_db` | PostgreSQL |
| `queuebot_pgadmin` | pgAdmin 4 (веб-интерфейс БД) |

Миграции применяются автоматически при старте бота. Чаты из существующего расписания и `BOT_CHAT_ID` добавляются в меню без повторного ввода; чат из `BOT_CHAT_ID` становится основным, если он ещё не выбран. Если указан только один чат, он выбирается автоматически. Названия загружаются из Telegram при открытии меню; при недоступности API вместо названия показывается ID.

Текущие запуски сохраняют даты, участников и отметки между перезапусками. Для очередей старой версии дата восстанавливается из исходной даты сообщения Telegram, без привязки к сегодняшнему дню. Если исходное сообщение недоступно, участники сохраняются, но автоматически восстановить дату такой очереди нельзя.

## Команды бота

### Пользователи

| Команда | Описание |
|---------|----------|
| `/start` | Показать приветствие |
| `/swap <место>` | Запросить обмен местами в текущей теме очереди; второй участник подтверждает обмен |

Запись, выход, занятие ближайшего свободного места и отметка «Сдал» доступны участникам без роли администратора. Повторное нажатие «Сдал» снимает отметку. Галочка появляется после имени, не освобождает место и остаётся у человека при обмене.

### Администраторы

| Команда | Описание |
|---------|----------|
| `/edit_schedule` | Выбрать чат и открыть его расписание; доступные изменения определяются разрешениями |
| `/edit_config` | Настройки и вкладка «Администраторы»; только для `DEVELOPER_USER_ID` |
| `/chat_id` | Показать ID текущего чата и темы; нужно разрешение «Просмотр ID чата». Через 15 секунд бот пытается удалить ответ и команду |
| `/manage_queue` | Выбрать открытую очередь и управлять участниками; нужно разрешение «Исключение участников» |
| `/queue` | Обновить сообщение действующей очереди или восстановить удалённое; нужно разрешение «Восстановление и повторная отправка» |
| `/one_shot_queue [заголовок]` | Создать одноразовую очередь; нужно разрешение «Разовые очереди». Задержка и длительность задаются в конфиге |

`/queue` нужна, если сообщение очереди удалили и нажать его кнопки уже нельзя: бот публикует очередь из БД с прежними участниками, местами и галочками. Если сообщение существует, команда обновляет его. Кнопка «Отправить очередь повторно» отправляет существующую открытую очередь ниже в чат, а на старом сообщении оставляет указатель на актуальное. Завершённую очередь эти действия не открывают заново.

Заголовок разовой очереди можно оставить пустым или передать после команды:

```text
/one_shot_queue БГГ323 — Высоконагруженные приложения
```

### Чаты и расписание

`/edit_schedule` всегда открывает список чатов. При добавлении чата его ID вводится один раз, название можно изменить в карточке; новые записи наследуют выбранный чат. Бот должен находиться в добавляемой группе. Разработчик может выбрать основной чат в его карточке. `/one_shot_queue` и `/queue` из лички используют основной чат, из группы — текущую группу и тему.

В выбранном чате нажми «Добавить новую запись» и отправь поля через запятую:

```text
день недели, тип недели, время начала, время конца, ID темы, описание (необязательно), заголовок (необязательно)
```

Например, для обычной группы или основной темы:

```text
суббота, чётная, 09:00, 09:25, 0, highload, Общая очередь
```

`0` означает отправку без указания отдельной темы. Для конкретной темы нужен её настоящий ID; узнать его можно командой `/chat_id` в этой теме. Поле ID темы нельзя оставлять пустым или заменять произвольным числом; ID самой группы в строке расписания не нужен.

«Общая очередь» появится первым абзацем над текстом очереди. Описание `highload` показывается в редакторе и управлении участниками, в публичное сообщение очереди оно не попадает. Название чата, описание записи и заголовок очереди задаются независимо.

Если нужен только заголовок, оставь описание пустым:

```text
суббота, чётная, 09:00, 09:25, 0, , Очередь для группы БВТ2303
```

Время задаётся по Москве в формате `ЧЧ:ММ` или `ЧЧ:ММ:СС`. День и тип недели можно вводить по-русски или по-английски; для недели — `чётная` / `нечётная` или `even` / `odd`. Текст с запятыми заключай в двойные кавычки. Описание ограничено 500 символами, заголовок — 200; удалить заголовок в его редакторе можно сообщением `-`.

Кнопка «Сменить тип недели» сразу меняет текущую чётность для всех чатов. Дальше недели чередуются с понедельника по московскому времени. Настройка сохраняется в БД; уже начатые очереди продолжают работать.

### Роли и разрешения

Разработчик, заданный в `DEVELOPER_USER_ID`, всегда имеет все разрешения. Только он управляет настройками, назначает администраторов через `/edit_config` → «Администраторы» и выбирает основной чат. Роль разработчика через это меню не снимается.

У каждого администратора отдельно включаются разрешения:

| Разрешение | Что доступно |
|------------|--------------|
| Просмотр ID чата | Команда `/chat_id` |
| Разовые очереди | Команда `/one_shot_queue` |
| Восстановление и повторная отправка | Команда `/queue` и кнопка повторной отправки |
| Редактирование расписания | Добавление, изменение и удаление записей выбранного чата |
| Добавление и названия чатов | Добавление чата и изменение его названия |
| Смена текущего типа недели | Общая чётность через «Сменить тип недели» |
| Отметки сдачи других участников | Переключение галочки нажатием на занятое место другого участника |
| Исключение участников | Удаление с блокировкой или без неё, просмотр и снятие временных блокировок |

Разрешения действуют во всех добавленных чатах и проверяются при выполнении действия, в том числе у уже открытых меню. Редактирование расписания, управление чатами и смена недели разрешаются независимо: право открыть меню расписания само по себе не даёт остальные действия.

Администратору можно задать необязательную подпись, например «Маша — староста БГГ323». Она показывается рядом с Telegram ID в списке и карточке; изменить или убрать её может только разработчик. Подпись не влияет на права.

При первой раскатке прежние `AUTHORIZED_USER_ID` автоматически получают все разрешения. Новые администраторы создаются с выключенными разрешениями; повторный деплой не возвращает снятые права из окружения.

Без разрешения `/chat_id` и `/manage_queue` не выводят ответ. Нажатие общей кнопки «Управление участниками» без доступа показывает личное всплывающее окно с OK, без сообщения в чат.

### Управление участниками и служебные меню

Кнопка «Управление участниками» под сообщением сразу открывает эту очередь. Команда `/manage_queue` показывает список открытых очередей: группа, тема, заголовок и время по Москве вынесены в текст, кнопки выбора короткие; большой список разбит на страницы.

Одно нажатие на участника освобождает его место без подтверждения. Переключатель блокировки при открытии меню выключен: повторная запись разрешена. Если включить его, удалённый участник не сможет записаться в этот запуск очереди в течение выбранного срока, по умолчанию 3 минуты. Можно подряд нажать несколько участников. Срок берётся из настроек при открытии меню: изменение конфига применяется к следующим сессиям и не меняет уже выданные блокировки.

В разделе «Временные блокировки» показываются действующие ограничения выбранной очереди. Нажатие на участника разрешает ему записаться снова, но не возвращает его в очередь автоматически. Блокировки сохраняются при перезапуске, истекают сами и не переходят в другие очереди или следующие запуски. Меню обновляется автоматически; очередь, запуск, запись участника и блокировка определяются по сохранённым ID, а не тексту кнопок.

В группе `/edit_config` и управление участниками открывают личное временное меню, видимое только вызвавшему пользователю. Если Telegram не поддерживает этот режим, бот предлагает открыть команду в личке. Меню расписания остаётся обычным. Ввод для настройки нужно отправлять в том же чате и теме, где открыто меню. Служебные меню удаляются по таймауту или завершению; неудавшееся удаление повторяется, в том числе после перезапуска.

## Деплой на сервер (GitHub Actions)

Пуш в ветку `main` запускает unit/race-проверки, интеграционные тесты с PostgreSQL и сборку контейнера. Деплой через SSH выполняется после успешного завершения всех проверок для того же коммита. Готовность контейнера подтверждается после подключения к БД, применения миграций, проверки Telegram и загрузки расписания.

### Необходимые секреты в GitHub репозитории

| Секрет | Значение |
|--------|----------|
| `GO_BOT_SERVER_HOST` | IP или домен сервера |
| `GO_BOT_SERVER_USER` | SSH-пользователь |
| `GO_BOT_SSH_PRIVATE_KEY` | Приватный SSH-ключ |
| `BOT_TOKEN` | Новый токен BotFather для ручной смены токена через Actions |

Для смены токена без ручного входа на сервер обнови секрет `BOT_TOKEN` в **Settings → Secrets and variables → Actions**. Затем открой **Actions → Rotate Telegram token → Run workflow**, выбрав `main`. Workflow должен быть уже в основной ветке, а её версия — развёрнута на сервере. На сервере нужен `python3` версии 3.8 или новее.

Действие проверяет новый токен и ID бота, обновляет только `BOT_TOKEN` в серверном `.env` и пересоздаёт контейнер из того же образа. Сборка и развёртывание новой версии не запускаются. Готовность проверяется после пересоздания; действующий старый токен для этого не нужен. При ошибке запуска новый токен остаётся в `.env`: после исправления секрета действие можно повторить, автоматического возврата к отозванному токену нет.

### Настройка сервера (один раз)

На сервере нужны Git, Docker с плагином Compose и доступ SSH-пользователя к Docker без `sudo`.

1. **Сгенерировать SSH-ключ** (если нет):
   ```bash
   ssh-keygen -t ed25519 -C "github-actions"
   ```

2. **Добавить публичный ключ в `authorized_keys`**:
   ```bash
   cat ~/.ssh/id_ed25519.pub >> ~/.ssh/authorized_keys
   ```

3. **Добавить приватный ключ в GitHub Secrets** (`GO_BOT_SSH_PRIVATE_KEY`):
   ```bash
   cat ~/.ssh/id_ed25519
   ```

4. **Клонировать репозиторий на сервере**:
   ```bash
   git clone https://github.com/lDizil/queue-bot-go.git ~/queue-bot-go
   ```

5. **Создать `.env` на сервере**:
   ```bash
   cp ~/queue-bot-go/.env.example ~/queue-bot-go/.env
   # Заполнить .env
   ```

После этого любой пуш в `main` автоматически пересоберёт и перезапустит контейнер бота. Перед первым обновлением с изменением схемы нужно самостоятельно сохранить резервную копию БД.

Для отката на версию, не знающую применённые миграции, недостаточно переключить ветку: старый образ не сможет открыть новую схему. Нужно остановить бота, восстановить выбранную резервную копию БД и запустить соответствующий ей старый код. Восстановление возвращает данные к моменту копии; последующие изменения в неё не входят. Автоматический downgrade с удалением настроек и отметок не выполняется.
